Technical documentation

xstyle, checker and fixer of the coding stylexstyle, vérificateur et correcteur du style de code

C++20 / libutils program checking Tsukini's coding style: C++ first (cpp-style, cpp-comments, the cpp-class layout, libutils usage), then Python, shell, Rust, CMake and the generic rules of every language. Each issue comes with its file, line, rule and proposed fix; what is safe is fixed with --fix.Programme C++20 / libutils qui vérifie le style de code de Tsukini : le C++ d'abord (cpp-style, cpp-comments, la structure cpp-class, l'usage de libutils), puis Python, shell, Rust, CMake et les règles génériques de tous les langages. Chaque problème donne son fichier, sa ligne, sa règle et la correction proposée ; ce qui est sûr est corrigé avec --fix.

1. OverviewPrésentation

xstyle reads the files given (or the current directory, recursively), detects the language of each one, runs the rules of that language and prints the issues followed by a summary counting them by severity and by rule. The exit status is 0 when nothing at or above --fail-on is left: the pre-commit hook and the CI use it.xstyle lit les fichiers donnés (ou le dossier courant, récursivement), détecte le langage de chacun, lance les règles de ce langage et affiche les problèmes puis un résumé qui les compte par gravité et par règle. Le code de sortie vaut 0 quand il ne reste rien au niveau de --fail-on ou au-dessus : le hook pre-commit et la CI s'en servent.

2. Installation

Packages xstyle (RPM, DEB, Arch) from the gh-pages repository of the project, or from my-universe with every other package of TsukiNi22. They install /usr/bin/xstyle and its bash / zsh / fish completion.Paquets xstyle (RPM, DEB, Arch) depuis le dépôt gh-pages du projet, ou depuis my-universe avec tous les autres paquets de TsukiNi22. Ils installent /usr/bin/xstyle et sa complétion bash / zsh / fish.

curl -fsSL https://tsukini22.github.io/my-universe/install.sh | bash -s
sudo dnf install xstyle      # sudo apt install xstyle / sudo pacman -S xstyle
curl -fsSL https://raw.githubusercontent.com/TsukiNi22/xstyle/main/setup.sh | bash -s -- --install   # --pre: xstyle-pre
git clone https://github.com/TsukiNi22/xstyle.git && cd xstyle
cmake -S . -B build -DCMAKE_BUILD_TYPE=Optimized
cmake --build build --parallel $(nproc)
cmake --install build --prefix ~/.local     # ~/.local/bin/xstyle + the completions

Building needs clang++ (C++20), CMake 3.20+ and libutils 4.1.0+ (4.2.0+ on Arch).La compilation demande clang++ (C++20), CMake 3.20+ et libutils 4.1.0+ (4.2.0+ sur Arch).

3. UsageUtilisation

xstyle                                 # the current directory, recursive
xstyle -r src include                  # these directories (recursive with -r)
xstyle --rtk                           # compact output for an AI (no color, no source line)
xstyle -s major                        # only the major and unforgivable issues
xstyle -c CPP-THIS,LU                  # only these rules (code, prefix or pattern)
xstyle --fix                           # fix what is safe (--force, --dangerous-force: more)
xstyle --staged --fail-on major        # the staged lines only: the pre-commit hook mode
xstyle -s major -o report.md           # Markdown report (text / md / json)
xstyle -x CPP-THIS                     # explain a rule (-L: every rule)

Every option also has an environment variable (XSTYLE_IGNORE, XSTYLE_EXCLUDE, XSTYLE_RTK, XSTYLE_R34...): xstyle --help lists them.Chaque option a aussi une variable d'environnement (XSTYLE_IGNORE, XSTYLE_EXCLUDE, XSTYLE_RTK, XSTYLE_R34...) : xstyle --help les liste.

6. SuppressionSuppression

A comment of the file silences a rule where it is wrong on purpose (with the reason after it):Un commentaire du fichier fait taire une règle là où elle a tort exprès (avec la raison après) :

const pid_t child = ::fork(); // xstyle: ignore LU-SYSCALL (a process of its own)
// xstyle: ignore-next CPP-SINGLE-STATEMENT (its state is private)
// xstyle: ignore-file G-TODO

From the command line: -i CODES (never these rules), -e PATTERNS (skip these paths); build*, third_party, node_modules and hidden folders are always skipped.En ligne de commande : -i CODES (jamais ces règles), -e MOTIFS (ignorer ces chemins) ; build*, third_party, node_modules et les dossiers cachés sont toujours ignorés.

  • Rules.cpp: Catalogue: code, severity, fix level, languages, description, documentationCatalogue : code, gravité, niveau de correction, langages, description, documentation
  • Reporter.cpp: Outputs: terminal (colors, hyperlinks), --rtk, Markdown, JSON, summarySorties : terminal (couleurs, hyperliens), --rtk, Markdown, JSON, résumé
