# xstyle

> [!TIP]
> Documentation [TsukiNi22/xstyle](https://tsukini22.github.io/xstyle/docs/) (v1.1.0): user guide, concepts, every option and rule (searchable, EN / FR) and the interactive project graph.

Checker and fixer of my coding style, C++ first (`cpp-style`, `cpp-comments`, `cpp-class` layout, libutils
usage), then C, assembly (NASM x86-64), Python, shell, Rust and the generic rules of every language. Each issue is printed with its file, line
and column (terminal hyperlink), the rule broken and the fix proposed; a summary counts the issues by severity
(**unforgivable**, **major**, **minor**, **negligible**) and by rule, plus one **mandatory** reminder that is never counted
([R34](#rule-r34-mandatory)). Everything that can be fixed safely is fixed
with `--fix`, for every rule or only some codes, files or directories.

Moved out of [ai-utils](https://github.com/TsukiNi22/ai-utils) (`style/xstyle`, history kept) into its own repository: RPM / DEB / Arch (pacman) packages
on the `gh-pages` branch, also listed in [my-universe](https://tsukini22.github.io/my-universe/) with the other packages of TsukiNi22.

## Quick Setup - 1 (all)
> Setup into `/usr/local` (or `~/.local`)

### Clone the repository
```bash
git clone https://github.com/TsukiNi22/xstyle.git
cd xstyle
```

### Build & install
```bash
export BUILD_DIR=build
cmake -S . -B $BUILD_DIR -DCMAKE_BUILD_TYPE=Optimized
cmake --build $BUILD_DIR --parallel $(nproc)                       # ./xstyle at the root + build/completion/
sudo cmake --build $BUILD_DIR --target install --parallel $(nproc) # /usr/local/bin/xstyle + the completions
cmake --install $BUILD_DIR --prefix ~/.local                       # or without root: ~/.local/bin/xstyle
```

Or only the one of xstyle, with its setup script (no clone needed). It registers the package repository (`gh-pages` branch) so the system package manager can install the packages:
1. Detect the distribution from `/etc/os-release` (`rpm`, `deb` or `arch` based).
2. `rpm`: add `/etc/yum.repos.d/xstyle.repo` and import the GPG key.
3. `deb`: add the GPG key in `/etc/apt/keyrings/xstyle.gpg`, the source in `/etc/apt/sources.list.d/xstyle.list`, then `apt-get update`.
4. `arch`: add the GPG key to the pacman keyring (`pacman-key --add` + `--lsign-key`), the `[xstyle]` repository in `/etc/pacman.conf` (`SigLevel = Required`), then `pacman -Sy`.
5. With `--install` only: install the package `xstyle` (`--pre` for the unstable one).

```bash
wget -qO- https://raw.githubusercontent.com/TsukiNi22/xstyle/main/setup.sh | bash -s -- --install
```

or with `curl`:

```bash
curl -fsSL https://raw.githubusercontent.com/TsukiNi22/xstyle/main/setup.sh | bash -s -- --install
```

| -------- | ------ |
| `--no-sudo` | Run without `sudo` (the script must already run as root) |
| `--install` | Also install the package (by default only the mirror & GPG key are setup) |
| `--pre` | Select the pre-release/unstable package (`xstyle-pre`) |

## Usage

```bash
xstyle                                 # check the current directory (recursive), every known language
xstyle -r src include                  # only these directories (recursive with -r)
xstyle src/core/Engine.cpp             # one file
xstyle -S                              # only the summary (counters by severity and by rule)
xstyle --rtk                           # compact output for an AI (5x fewer tokens): no color, no source, one line per issue
xstyle -s major                        # only the major and unforgivable issues
xstyle -m force,manual                 # only these fix levels (auto, force, ask, manual), comma separated
xstyle -c CPP-THIS,LU                  # only these rules (code, prefix or pattern: CPP, LU-*, G-TAB)
xstyle -i G-TODO,CPP-AUTO              # every rule except these
xstyle -l cpp,rs                       # only the C++ and Rust files (-t: only the most used language)
xstyle --fix                           # fix everything that can be fixed
xstyle --fix CPP-NULL,G-TRAILING src   # fix only these rules, only in src
xstyle --fix --force                   # also the [force-fix] ones (can change the behavior: check with -n first)
xstyle --fix --dangerous-force         # also the [danger-fix] ones: guessed (types from the usage...), can be wrong
xstyle --fix --header default          # missing file headers with the XARTANIA banner (none | default | <text>), no question
xstyle -f -n -c CPP -r src/core        # preview (dry run) of the C++ fixes of one directory
xstyle -o report.md                    # report in this file (.txt, .md or .json), nothing in the terminal
xstyle -x CPP-THIS                     # explain a rule, -L lists every rule
xstyle --diff                          # only the lines changed since HEAD (staged + not staged, new files)
xstyle --diff-ref main                 # only the lines changed since a branch / tag / commit
xstyle --staged --fix                  # only the staged lines (pre-commit hook)
xstyle --fix --commit                  # fix, then commit the fixed files: chore(style): apply the xstyle fixes (...)
xstyle --fix --commit-all --message "chore(core): ..."  # fix + commit every tracked change with the fixes
xstyle --libutils-check                # is the libutils skill reference up to date? (exit 0 yes, 1 no)
xstyle --r34                           # I have read the Terms and Conditions of Rule 34, I accept them: R34 is not displayed
```

- **Paths**: files or directories given as bare arguments; with no path the current directory is scanned
  recursively. Hidden folders, `build*`, `cmake-build-*`, `third_party`, `extern`, `vendor`, `node_modules`... and the
  `generated_*` files are skipped, `-e build,*.gen.hpp` excludes more (folder name, path prefix or glob).
- **Fix level** of every issue, right after its code (`Fix` column of the table below, `fix` field of the JSON):

  | Tag | Fixed by | Meaning |
  |---|---|---|
  | `[auto-fix]` | `--fix` | safe, the behavior can't change (spaces, includes order, `nullptr`, `[ ]` -> `[[ ]]` when equivalent...) |
  | `[force-fix]` | `--fix --force` | can change the behavior: `set -euo pipefail` (a failing command now stops the script), `encoding="utf-8"` (a file in another encoding now fails), `[ a -o b ]` / unquoted patterns, a comment replaced; preview with `-n` |
  | `[danger-fix]` | `--fix --dangerous-force` (implies `--force`) | guessed, can be wrong: Python types guessed from the usage / the name / a local variable, `T \| None` (Python 3.10+), `static_cast` of a C pointer cast (`reinterpret_cast` needed if it doesn't compile) |
  | `[ask-fix]` | `--fix` + a question | the missing file header: banner `[n]one`, `[d]efault` (XARTANIA) or `[t]ext` + description, per file (upper case answer: same for the next files); `--header none\|default\|<text>` and `--header-desc "..."` answer without question (CI, no terminal: skipped) |
  | `[manual]` | by hand | needs a decision a tool can't take (a type to write, a name to choose, a code to rewrite with libutils...) |

  Python type hints, per parameter / return:
  - **certain** (`[auto-fix]`): a literal default (`level=2` -> `level: int = 2`), `-> None` without any `return value` /
    `yield`, every `return` of the same certain type: literal, display (`[...]` list, `{...}` dict / set, `(a, b)` tuple),
    builtin (`len()` int, `str()`, `isinstance()` bool...), stdlib (`os.path.join()` str, `os.path.exists()` bool...),
    `not` / `is` / `in` (bool), `"text" + x` (str);
  - **guessed** (`[danger-fix]`): from the usage in the body (`x.split()` str, `x.append()` list, `x.items()` dict,
    `open(x)` str, `range(x)` int), from the name (`is_*` / `verbose` bool, `*_path` / `name` str, `count` / `size` int),
    a local variable assigned once (`parts = line.split(",")` then `return parts`), comparisons `==` / `<` (bool, can be
    overloaded), methods on an unknown value (`x.strip()` str), `T | None`;
  - **unknown** (`[manual]`, listed as "by hand"): anything else; a stub (`...`, `raise NotImplementedError`) or a
    generator is never typed.

- **Filter by level**: `-m auto,force,dangerous,ask,manual` (one or several, `forced` / `danger` accepted) keeps only those issues, in the
  display, the counters, the report and `--fix` (`xstyle --fix --force -m auto` applies only the safe fixes).
- **Templates**: a file with `{{NAME}}` placeholders is not valid code yet, only the generic rules are checked there.
- **Fix**: the fixes are applied in passes (a fix can reveal another issue: `[[nodiscard]]` -> `_nodiscard` ->
  `#define _Attribute` missing -> added), only the fixable rules (`yes` in the table) are touched, the logic never.
  Review the result with `git diff`.
- **AI mode** (`--rtk`, or `XSTYLE_RTK=1`): what an assistant needs and nothing else: a legend line, `>file` once, then
  `line:col CODE severity fix message => fix|hint` per issue (the message / hint shared by every issue of a rule written
  once in `* CODE ...` lines at the end), `fixed N: CODExK`, one `= N issues ...` summary line, errors on one plain line.
  No color, no hyperlink, no source line, no table. The skills and the `CLAUDE.md` files run xstyle this way.
- **Hyperlinks**: the locations are OSC 8 links in the terminal (`--link file`, default), or `vscode://` links
  (`--link vscode`, opens the file at the line), `--no-color` / `NO_COLOR` for plain text.
- **Changed lines** (`--diff`, `--diff-ref`, `--staged`): only the issues on the lines changed in git (whole file
  issues when the file changed), with no path the changed files themselves; the fixes follow the same filter.
- **Commit** (`--commit`, `--commit-all`, with `--fix`): the message is `chore(style): apply the xstyle fixes (N issues)`
  with one line per rule (or `--message`). `--commit` only takes the files that had **no** change before the fixes (their
  own changes would end up in the commit, they are listed and left), `--commit-all` takes every tracked change too.
  Never with `--dry-run`.
- **Exit status**: `0` clean, `1` issues left (from `--fail-on <severity>`, default every severity), `255` error.
  The **mandatory** rule (R34) is never counted: not in the exit status, the totals, `--fail-on` nor the pre-commit hook.
- **Environment**: `XSTYLE_CODES`, `XSTYLE_IGNORE`, `XSTYLE_SEVERITY`, `XSTYLE_EXCLUDE`, `XSTYLE_LIBUTILS`,
  `XSTYLE_LINK`, `XSTYLE_REPORT` give the default of the flag of the same name; `XSTYLE_R34=1` is `--r34`.

### Rule R34 (mandatory)

`R34` is the only rule of the severity **mandatory**: *Rule 34: if it exists, there is porn of it. No exceptions*. It is a
reminder, not a style rule:
 - it is displayed **once per run**, for the whole project, with a green link to the article of the rule
   (https://en.wikipedia.org/wiki/Rule_34), and in the `--rtk` output as a `! R34 ...` line;
 - it is **never counted**: not in the totals (its own `mandatory` row in the summary), the exit status, `--fail-on` nor
   the hook; `-s` does not hide it, `-c` / `-i` / `-m` select it like any other rule;
 - it is **acknowledged** (not displayed any more) by the integer **34**, or **r34** (any case) in an identifier, a string
   or a comment of a checked file, by a file named **R34.md** in the directory where xstyle is run, by the flag
   **`--r34`** or by `XSTYLE_R34=1`;
 - `xstyle --fix --force` writes `R34.md` (a long explanation of the rule: statement, origin, spread, interpretation),
   which acknowledges it; an existing `R34.md` is never replaced; `xstyle -x R34` explains it.

Suppression, in a comment of the file:

```cpp
std::cout << "\033[1m"; // xstyle: ignore LU-ANSI
// xstyle: ignore-next CPP-AUTO
auto lambda = [](int x) {return x * 2;};
// xstyle: ignore-file CPP-GUARD-MISSING (no guard on purpose)
```

## libutils

The `LU-*` rules are enabled when libutils is **installed** (`/usr/include`, `/usr/local/include`,
`~/.local/include` or `CPATH`) **and used by the project** (`find_package(utils)` / `utils::utils` in the root
`CMakeLists.txt`, or `utils.hpp` included); `--libutils on|off` forces them. Inside libutils itself they are off.
- includes: one root `<utils/utils.hpp>` preceded by the `#define _Section` of every section used (detected from
  the `utils::<section>::` names and the attribute macros of the file), never a libutils header one by one;
- `[[nodiscard]]`, `[[maybe_unused]]`, `alignas(...)`... -> the libutils macros (`_nodiscard`, `_unused`, `_alignas`...);
- deprecated names -> new names, read from the `_migration` aliases of the **installed** headers, plus the names
  libutils v4.0.0 removed (`isloaded()` -> `isLoaded()`, `utils::network::socket::is_ip` -> `utils::network::is_ip`,
  `setStyle` -> `set_style`, `fixed_string` -> `FixedString`...: a v3 code moved to v4 is told what to write);
- code that libutils already gives: standard exceptions, `argv` parsed by hand, raw ANSI sequences, BSD sockets,
  `pipe` / `fork` / `epoll` / `shm_open` / `dlopen`, thread pools, degree / radian conversions, base64, verbose
  flags, string distances (hint with the libutils class to use).

## Languages

| Language | Files | Rules |
|---|---|---|
| C++ | `.cpp .cc .cxx .hpp .hh .hxx .ipp .tpp .inl .h` | generic + `CPP-*` + `LU-*` (libutils installed and used) |
| C | `.c` (+ `.h` of a project without C++ sources) | generic + `C-*` (the layout rules shared with the C++ under their own `C-` code, then the C rules) |
| Assembly (NASM x86-64) | `.asm .nasm .s .S` | generic + `ASM-*` (a GAS file, AT&T or `.intel_syntax`: `ASM-HEADER` + generic only) |
| Rust | `.rs` | generic + `RS-*` (tests: `#[cfg(test)]` module, `tests/`, `benches/`, `examples/` excepted for unwrap / panic) |
| Python | `.py` | generic + `PY-*` |
| Shell | `.sh .bash` | generic + `SH-*` |
| Lua, JS / TS, CMake | `.lua`, `.js .mjs .ts .tsx .jsx`, `CMakeLists.txt .cmake` | generic |
| Makefile, YAML | `Makefile .mk`, `.yml .yaml` | generic (no indentation by 4, Makefile recipe tabs allowed) |
| JSON, Markdown | `.json`, `.md` | generic (Markdown: trailing spaces allowed) |

Any other file is skipped when a directory is scanned; given explicitly, it gets the basic generic rules.

## Rules

Severity: **unforgivable** > **major** > **minor** > **negligible**; **mandatory** is outside this scale (displayed, never counted).
Languages: `*` = every file checked.

| Code | Severity | Fix | Languages | Rule |
|---|---|---|---|---|
| `R34` | mandatory | force | * | Rule 34: if it exists, there is porn of it. No exceptions ([R34](#rule-r34-mandatory)) |
| `G-CRLF` | major | auto | * | Windows line endings (CRLF), use LF |
| `G-TAB` | major | auto | * | Tab used for the indentation, use 4 spaces (except Makefile recipes) |
| `G-TRAILING` | minor | auto | * | Trailing whitespace |
| `G-EMPTY-LINES` | minor | auto | * | Two or more consecutive empty lines, one is the maximum |
| `G-EOF-NEWLINE` | negligible | auto | * | No newline at the end of the file |
| `G-EOF-EMPTY` | negligible | auto | * | Empty lines at the end of the file |
| `G-TODO` | minor | - | * | TODO / FIXME / XXX tag, describe the limitation in a normal comment instead |
| `G-INDENT` | negligible | - | cpp,c,py,sh,lua,js,rs,cmake | Indentation that is not a multiple of 4 spaces |
| `CPP-USING-NAMESPACE` | unforgivable | - | cpp | using namespace, always write the fully qualified names |
| `CPP-GUARD-MISSING` | major | auto | cpp | Header without include guard (#ifndef NAME_H / #define NAME_H) |
| `CPP-PRAGMA-ONCE` | minor | auto | cpp | #pragma once instead of the include guard NAME_H |
| `CPP-GUARD-NAME` | minor | auto | cpp | Include guard not named after the file (Name.hpp -> NAME_H) |
| `CPP-ENDIF-COMMENT` | negligible | auto | cpp | Guard #endif without its /* NAME_H */ comment |
| `CPP-PREPRO-INDENT` | negligible | auto | cpp | #if block not at the indent of the code around with its content one level more (directives: 4 per #if / guard level) |

## Development

```bash
make                                                      # Configure & build into build/
export BUILD_DIR=build
cmake -S . -B $BUILD_DIR -DCMAKE_BUILD_TYPE=Debug         # Debug build (-g -ggdb3)
cmake -S . -B $BUILD_DIR -DCMAKE_BUILD_TYPE=Asan          # AddressSanitizer build
cmake --build $BUILD_DIR --target release                 # Debug, Asan & Optimized builds
cmake --build $BUILD_DIR --target package_release         # RPM / DEB / Arch packages of every variant (build/*.rpm, *.deb, *.pkg.tar.zst)
cmake --build $BUILD_DIR --target get_unregistered_files  # .cpp files missing from the SRC / SRC_SHARED lists
./xstyle --rtk -r src include tests CMakeLists.txt        # xstyle stays clean on itself (checked by the CI)
```

| Path | Content |
| ---- | ------- |
| `src/xstyle/` | Sources: `main.cpp` (entry), `Core.cpp` (arguments, run), `Checker.cpp`, `Reporter.cpp`, `Rules.cpp`, `check/` (one file per family of rules) |
| `include/xstyle/` | Headers |
| `assets/fonts/ansi_shadow.flf` | Banner font of the file headers (`--header`), embedded at build time (`build/generated/xstyle/Font.hpp`) |
| `tests/xstyle/` | Unit tests (GoogleTest) + command line tests (`ctest`) |
| `cmake/package/` | CMake package config and the CPack scripts (Arch packages) |
| `docs/` | Documentation site (`docs/site/`: Markdown sources + generators, built pages in `docs/`) and the project graph |

> [!NOTE]
> Every new `.cpp` must be added to the `SRC` (executable only) or `SRC_SHARED` (executable and tests) list of the `CMakeLists.txt` (`get_unregistered_files` lists the missing ones).

### Unit tests

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTS=ON
cmake --build build --parallel $(nproc)                       # ./unit_tests at the root
(cd build && ctest --output-on-failure)
```

### Pre-commit hook

The shared hook (`.githooks/pre-commit`) runs xstyle on the staged lines at each `git commit` and refuses a `major` (or worse) issue.

```bash
git config core.hooksPath .githooks   # once per new clone
git commit --no-verify                # skip the hook once (or XSTYLE_HOOK=0 git commit ...)
xstyle --fix --staged                 # fix what can be, then git add -u
```

## Workflows/Release
### Workflows
- `Dispatch (CI/CD)`: runs on every push (branch `main` or tag `v*`, not for `*.md` / `*.txt` / `docs/` only changes) and decides what to trigger from the ref / commit message
- `Unit Tests (CI)`: builds and runs the unit tests, always first in the `unit-tests` image
- `Build (CI)`: only builds the project in the `ci` image, checks the outputs and runs xstyle on its own sources (`--fail-on major`), without producing packages
- `Build - Packages (CI/CD)`: builds the packages (RPM/DEB/Arch, in the `ci` image), signs them and publishes them on the `gh-pages` repository
- `Release - GitHub (CD)`: creates the GitHub release of a tag from its section of the `CHANGELOG.md`, once the packages are published
- `Docs - Pages (CD)`: copies `docs/` on the `gh-pages` branch on every push changing it (https://tsukini22.github.io/xstyle/docs/)
- `Sync Packages (CD)` (on `gh-pages`): rebuilds the metadata and signatures of the package repository after a manual push on the branch

> [!NOTE]
> `Build (CI)` only runs when `Dispatch (CI/CD)` decides **not** to build the packages, to check that the code still compiles.

> [!IMPORTANT]
> The workflows need the repository variable `RUNNER` (`gh variable set RUNNER --body <runner>`), the containers `ghcr.io/tsukini22/ci`, `unit-tests`, `package`, `git`, and the secrets `GPG_PRIVATE_KEY` (base64), `GPG_KEY_ID`, `GPG_PASSPHRASE` to sign and publish the packages.

> [!TIP]
> A commit containing `[ignore]` skips the whole CI.

### Pre-Release (unstable)
The pre-release of the packages (`<package_name>-pre`) is triggered by:
- a tag with a suffix, matching `vx.x.x-<suffix>` (ex: `v1.0.1-pre`, `x` = `major`, `minor`, `fix`)
- or a commit containing `[build]`

> [!NOTE]
> Only the 5 last versions of each `-pre` package are kept in the package repository, every release is kept.

### Release (stable)
The release of the packages (channel `stable`) and the GitHub release are only triggered by a tag matching exactly `vx.x.x` (ex: `v1.0.0`), whose section must exist in the `CHANGELOG.md`.

### Downstream notification
`Dispatch (CI/CD)` has a commented `notify-downstream` job (`repository_dispatch` to another repository, like libutils -> docker-image), triggered after a package publication or by a commit containing `[release]`.
